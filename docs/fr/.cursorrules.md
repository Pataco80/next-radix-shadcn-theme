Développez des applications TypeScript, Node.js et Next.js en suivant les conventions et directives fournies.

**Style de code et structure**

- Écrivez du code TypeScript concis et technique en utilisant des modèles de programmation fonctionnels et déclaratifs.
- Évitez les classes ; préférez l'itération et la modularisation à la duplication de code.
- Utilisez des noms de variables descriptifs avec des verbes auxiliaires (par exemple, `isLoading`, `hasError`).
- Structurez les fichiers en : composant exporté, sous-composants, helpers, contenu statique et types.

**Conventions de nommage**

- Utilisez des minuscules avec des tirets pour les répertoires (par exemple, `components/auth-wizard`).
- Privilégiez les exportations nommées pour les composants.

**Utilisation de TypeScript**

- Utilisez TypeScript pour tout le code ; préférez les types aux interfaces.
- Évitez les énumérations ; utilisez des maps à la place.
- Utilisez des composants fonctionnels avec des types TypeScript.

**Syntaxe et formatage**

- Évitez les accolades inutiles dans les conditions ; utilisez une syntaxe concise pour les instructions simples.
- Écrivez du JSX déclaratif.

**UI et style**

- Utilisez Shadcn UI, Radix et Tailwind pour les composants et le style.
- Implémentez un design responsive avec Tailwind CSS en utilisant une approche mobile-first.

**Optimisation des performances**

- Minimisez `use client`, `useEffect` et `setState` ; privilégiez les React Server Components (RSC).
- Enveloppez les composants client dans `Suspense` avec fallback.
- Utilisez le chargement dynamique pour les composants non critiques.
- Optimisez les images : utilisez le format WebP, incluez les données de taille et implémentez le chargement paresseux.

**Requêtes de base de données et création de modèles de données**

- Utilisez Prisma SDK pour interroger la base de données.
- Pour les modèles de données, lisez les fichiers `.prisma`.

**Conventions clés**

- Utilisez 'nuqs' pour la gestion des paramètres de recherche d'URL.
- Optimisez les Web Vitals (LCP, CLS, FID).
- Limitez 'use client' : privilégiez les composants serveur et Next.js SSR pour la récupération de données ou la gestion d'état.
- Utilisez 'use client' uniquement pour l'accès à l'API Web dans les petits composants.

**PostgreSQL**

- Utilisez une syntaxe PostgreSQL valide avec des guillemets pour les noms de tables et de colonnes.

**React 19**

- Utilisez React 19 avec les Server Components. Implémentez les requêtes Prisma et la logique backend dans les fichiers `page` ou `layout` comme ceci :

```tsx
// Utilisez "async" pour les composants serveur
export default async function Page() {
	// Utilisez "await" pour les opérations asynchrones
	const result = await prisma.user.findMany()
	return (
		<div>
			{result.map(user => (
				<p>{user.name}</p>
			))}
		</div>
	)
}
```

- Évitez d'utiliser des hooks React dans les composants serveur.

**Création d'un composant**

- Utilisez toujours `export function` sans "default" ou exportation nommée.
- Utilisez toujours un objet "props" comme premier argument de votre composant, et ajoutez le type directement dans l'objet.

Exemple :

```tsx
export function MyComponent(props: { prop1: string; prop2: number }) {
	return <div>{props.prop1}</div>
}
```
